# 재즈 연습 반주

`JazzBacking`은 코드 차트에 맞춰 피아노 컴핑·더블베이스·어쿠스틱 드럼을 예약한다. `JazzInstruments`가 실제 악기 녹음 샘플을 재생한다. 원곡의 녹음이나 멜로디를 포함한 반주 음원을 사용하는 방식은 아니다.

## 악기와 샘플

| 악기   | 녹음                                     | 포함 범위                                | 출처의 배포 조건                      |
| ------ | ---------------------------------------- | ---------------------------------------- | ------------------------------------- |
| 피아노 | Splendid Steinway Grand                  | 10개 루트 × PP/Mp 2단계 다이내믹         | 배포자가 명시한 AKAI 공개 도메인 녹음 |
| 베이스 | D. Smolken의 1958 Otto Rubner 더블베이스 | 피치카토 7개 루트 × 2개 변주             | CC0 1.0                               |
| 드럼   | menegass의 Guigui 어쿠스틱 드럼 세트     | 라이드 2개, 하이햇 2개, 킥·스네어 각 1개 | CC0 1.0                               |

소스 파일은 `public/samples/jazz-v1/`에서 직접 제공한다. 총 40개 녹음을 M4A와 OGG 두 형식으로 포함하며 전체 파일은 약 5.29MB다. 기본 M4A 2,778,918바이트(약 2.8MB)를 먼저 읽고 디코더가 지원하지 않으면 OGG로 재시도한다. 외부 CDN이 재생 중 필요하지 않다. 모든 파일의 원본 URL·커밋·해시는 [manifest.json](../public/samples/jazz-v1/manifest.json)에 있다.

피아노는 벨로시티에 따라 서로 다른 녹음 층을 선택한다. 베이스는 동일 루트에서 두 녹음을 번갈아 사용한다. 인접한 녹음 루트에서 필요한 음으로 재생 속도를 조절하며 목표음의 실제 MIDI 피치를 기준으로 계산한다. 모든 음을 단일 샘플로 길게 늘이는 방식이나 사인파 합성으로 대체하지 않는다.

Ballad에 실제 브러시 스윕 녹음은 포함하지 않았다. 낮은 레벨의 스네어·하이햇을 사용한다. 라이브 재즈 트리오의 연주 판단이나 스튜디오 음질을 보장하지 않으며 샘플에 기반한 연습 반주다.

## 사운드와 예약

각 샘플의 피크를 0.8로 맞추고, 피아노 코드의 음 수에 따라 개별 음의 게인을 줄여 헤드룸을 둔다. 피아노·베이스·드럼은 별도의 출력 버스를 사용하므로 UI 믹서와 마스터 컴프레서가 그대로 동작한다. 음의 시작과 릴리스는 오디오 시계로 예약한다. 정지하면 미래에 예약된 음까지 해제한다.

베이스는 전조와 슬래시 베이스 적용 후에도 E1–B2(MIDI 28–47) 안에서 피치 클래스를 유지한다. 피아노는 가이드 톤과 가까운 보이스 리딩을 사용한다. 녹음 샘플 믹스의 낮은 출력에 맞춰 마스터 게인을 조정했으며 아래의 실제 렌더링 수치로 피크 여유를 확인했다.

`parseJazzChord()`가 3도·7도·텐션·슬래시 베이스를 해석하고 키 이동을 화성 악기에 적용한다. `planBackingBar()`가 각 스타일의 리듬·보이싱·베이스 진행을 만든다. 드럼의 피치는 전조하지 않는다. 코드 경계는 한 마디에 여러 코드가 있어도 실제 박 위치에 맞춘다.

스케줄러는 가까운 미래를 미리 예약한다. 화면 마디 표시는 별도 경과 시간을 누적하지 않고 예약한 오디오 위치에 맞춘다. 템포·키·믹스 변경은 다음 예약부터 반영되므로 이미 울리는 음과 미리 예약한 짧은 구간은 즉시 다시 만들지 않는다. 배경 탭에서 복귀할 때 놓친 음을 몰아서 재생하지 않는다.

## 최초 준비와 캐시

악기를 처음 재생할 때만 샘플을 읽고 디코딩하며, 준비가 끝나기 전에 반주를 시작하지 않는다. 압축 바이트와 준비된 PCM 버퍼를 캐시하여 정지 후 다시 재생할 때 전체 파일을 다시 내려받지 않는다. 디코딩은 한 번에 5개로 제한한다. 피아노의 긴 꼬리는 최대 4.5초, 베이스는 3초로 제한하고 끝부분을 페이드 처리해 메모리를 줄인다.

개별 다운로드 제한은 15초, 전체 준비 제한은 25초다. `create(context, outputs, {signal})`로 취소할 수 있다. 취소한 이전 컨텍스트의 준비 작업이 새 시작을 덮어쓰지 않도록 대기 중 디코딩을 컨텍스트별로 구분한다. 샘플을 읽지 못하면 짧은 오류를 표시하며 이전 합성음으로 조용히 돌아가지 않는다.

`/samples/jazz-v1/**`는 1년 immutable 캐시를 사용하는 버전별 경로다. 배포한 v1의 바이트·manifest·고지를 바꾸지 않는다. 샘플을 갱신할 때 새 버전 경로로 옮기고 렌더러 URL도 함께 바꾼다.

## 모바일 출력과 중단

Audio Session API를 지원하면 반주·메트로놈·연습음을 `playback`으로 선언한다. 튜너가 입력을 사용 중이면 `play-and-record`가 우선하며, 반주 재생 때문에 마이크를 정지하지 않는다. 각 재생·입력 수명이 끝나면 해당 요청만 해제하고 마지막 요청이 끝나면 이전 세션 형식으로 복원한다. 미지원 브라우저에서는 기존 Web Audio 동작을 유지한다.

반주는 최초 사용자 클릭에서 `resume()`을 호출하고 샘플 준비 뒤 중단 상태를 다시 확인한다. 각 재개 대기는 4초로 제한하며 정지 버튼은 즉시 대기를 취소한다. 오디오 시계가 멈췄을 때 화면 진행만 움직이지 않도록 스케줄링과 위치 알림을 보류한다. 재생 중 지속적인 중단이 있으면 짧은 오류와 함께 다시 재생할 수 있게 한다.

출력 막대는 마스터 뒤 `AnalyserNode`의 PCM RMS를 표시한다. 오디오 파일과 그래프에 신호가 있는지는 확인할 수 있지만 운영체제의 음소거·스피커 경로는 감지하지 못한다. 이번 브라우저 점검에서는 출력 약 −20~−22dB, 템포·전조 변경 후에도 신호 유지, 콘솔 경고·오류 없음이 확인됐다. 실제 iPhone에서 무음 스위치·마이크 동시 입력 조합은 별도 확인이 필요하다.

설계 근거: [W3C Audio Session 초안](https://www.w3.org/TR/audio-session/), [WebKit의 Web Audio ambient 동작 설명](https://bugs.webkit.org/show_bug.cgi?id=252746).

## 검증과 출처

음표 계획·스케줄링·정지 및 시작 취소는 가상 오디오 시계로 검사한다. 샘플 파일 80개는 SHA-256으로 확인했고 M4A 40개는 FFmpeg가 실제 AAC 음원으로 읽는지 검사했다. 피아노·베이스 파일의 피치를 분석하여 루트 매핑의 옥타브도 확인했다. 실제 렌더러와 연주 계획으로 16마디 WAV를 생성해 피크·RMS·음역을 수치로 점검한다. 사람이 직접 청취하여 음질을 승인했다고 주장하지 않으며, 모든 브라우저·스피커의 재생 품질 인증도 아니다.

- Autumn Leaves 앞 16마디, 120 BPM 기본 믹스: 약 35초 WAV의 피크 0.2795, RMS 0.0240, 클리핑 없음. 베이스 MIDI 36–47, 피아노 58–70.
- 마스터·악기별 레벨을 모두 1로 올리고 ±11반음 키 이동·고속 템포를 적용한 8마디 스트레스 렌더: Swing 피크 0.737, Bossa 0.693, Ballad 0.702, Straight 0.758. 모두 디지털 클리핑 없음.
- 이 수치는 실제 M4A에서 디코딩한 PCM을 같은 `JazzInstruments`와 연주 계획으로 OfflineAudioContext에서 렌더링한 결과다. 브라우저 출력이나 사람의 청취 평가는 포함하지 않는다.

반주 계획·스케줄러 테스트 15개와 샘플 뱅크 테스트 4개를 포함해 전체 자동 테스트 71개가 통과했다.
